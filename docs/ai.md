# AI: the word card, prompts, providers, cache and pictures

Read before changing `src/lib/ai/`, `src/lib/images.js`, the AI parts of the pop-up or the Dicionários tab. Moved from AGENTS.md on 2026-11-11; keep it current in the same commit as the change it describes.

- **Definition and translation languages (`LANGUAGES` in src/main/ui.js):** Lookupper's 58 entries: the 53 languages it translates into, plus en-US/en-GB, es-ES/es-419, pt-BR/pt-PT, Serbian Cyrillic/Latin and Chinese Simplified/Traditional. They are named in English. The AI prompt names them with `Intl.DisplayNames` in English (`languageName` in word-card.js). `settings::migrate` turns the older tags `es-MX`, `zh-CN` and `zh-TW` into `es-419`, `zh-Hans-CN` and `zh-Hant-TW`.
  - Three settings: `definitionLanguage` (the card's definition and components), `translationLanguage` (the card's word translation and the context translator) and `explanationLanguage` ("Explicar", `{{explanationLanguage}}`). The explanation one was split from the translation one at the user's request. Settings saved before have it empty, and `migrate` copies the translation language. `normalizeAiOptions` moves the old default explanation prompt, which wrote in `{{translationLanguage}}`, to the new one.
- **Pictures ("Imagens", built-in dictionary `ai-images`, `DictionaryKind::AiImages`):** Migaku's pop-up image tab, by behavior (its extension was read, no code or text copied).
  - The AI turns the word into an English search query with its own prompts, `ai.imageQuerySystemPrompt` and `ai.imageQueryPrompt` (Migaku's "Image query" system/user pair). The system prompt replaces the shared `systemPrompt` for this request only (`explain(..., {system})`). Variables: `{{target}}`, `{{sentence}}` (the sentence, not the paragraph), `{{wordLanguage}}` (the OCR language), `{{definitionLanguage}}`, `{{translationLanguage}}`. `cleanQuery` keeps the answer's first line. If the AI fails, is not configured, or `ai.imageQueryUseAi` is off, the word itself is searched, as Migaku does on failure. The answer is cached like the other AI answers (kind `images`).
  - Search: `GET https://www.bing.com/images/async?q=…&first=0&count=100&adlt=strict` through tauri-plugin-http (Bing sends no CORS headers), Migaku's exact parameters. Bing has had no free image API since 2025. Each result's `m` attribute is JSON: `murl` (the picture), `turl` (Bing's thumbnail), `t`, `purl`. The strip shows `turl`; the viewer and Anki use `murl`, falling back to `turl`. Migaku itself keeps only `murl` (regex `murl&quot;:&quot;(.*?)&quot;`), which `parseBingImages` still uses as a fallback. The first 10 are shown. An empty answer is asked once more, because Bing now and then answers with nothing. No User-Agent spoofing: Migaku rotates five browser UAs, and that was not needed in tests on 2026-10-20. Migaku's `IMAGE_QUERY_PREFIX`/`SUFFIX` are hidden env keys and are not ported. Meme mode is ported: a "Modo meme" switch under the strip (`ai.imageMemeMode`, `withMemeMode`) appends " meme" to the search and searches again at once, reusing the cached AI query. The pop-up saves only that key (`saveMemeMode`: fresh `get_settings`, then `save_settings`), and the main window copies it on `settings-changed`, so its own saves do not undo it.
  - Pop-up: like Explicar, the section shows "Mostrar imagens" and loads on click, unless `ai.autoShowImages` is on. Pictures sit in a sideways strip (156×140 tiles; the wheel scrolls it while it can). The check mark in the top-right corner appears on hover and stays on a checked picture. Only a click on it checks the picture; a click anywhere else opens the viewer over the pop-up. The viewer moves to the neighbours with the arrows at the picture's sides, ← →, or by dragging the picture sideways at least `SWIPE_PX` (60 px; pointer events, so mouse, pen and touch). Esc or a click outside closes it, and the click that ends a drag does not count as one. Its bar has the position (2/10), "Marcar para o Anki" and the source page. A picture that fails to load is removed, as in Migaku.
  - Anki: `{image}` holds the checked pictures, each downloaded, scaled to at most 800 px (`ANKI_IMAGE_MAX_SIDE`; Migaku scales to 800 px wide, as webp) as JPEG, and stored as `lookitan_image_<n>_<date>.jpg`. GIFs, and pictures the WebView cannot decode, are stored as they are. Nothing is checked by default, so `{image}` stays empty unless the user checks something. `suggestMarker` gives `{image}` to fields named image/picture/photo, and `{screenshot}` only to "screenshot".
- **Generated pictures ("Imagem AI", `ai-image-gen`): removed on 2026-10-20 at the user's request, in favour of the Migaku-style "Imagens" only.** The whole feature is in the `image-ai-backup` branch: named prompts, OpenAI/Gemini/OpenRouter image models, `{ai-image}`, pictures kept in IndexedDB `lookitan-image-gen`. Nothing on `tests` names it any more. Settings saved meanwhile still load through a general rule: `readable_dictionaries` (settings.rs) leaves out any dictionary entry of a kind this version cannot read. Without it, serde would make the whole file invalid and `load()` would fall back to the defaults. Its keys in `ai` (`imageGen*`, `autoGenerateImages`) are ignored. Its `sectionProviders` block goes on the next save, since `normalizeAiOptions` rebuilds that object.
- **AI word card fields:** the card prompt asks for headword, IPA, CEFR, part of speech, labels, definition, translation (`{{translationField}}`) and synonyms in every language; `{{readingField}}` gets the editable "Prompt da leitura" (`ai.readingPrompt`) only in Chinese and Japanese, with `{{readingSystem}}` = pinyin with tone marks / hiragana, from the OCR language; `{{componentsField}}` gets the editable "Prompt dos componentes" (`ai.componentsPrompt`) only when "Componentes" (`ai.cardComponents`, default on) is on, with `{{componentParts}}` (each character in Chinese and Japanese; in Korean each syllable of a Sino-Korean word, else stem and endings; else roots, affixes or compound members) and `{{componentReading}}` (a pinyin/kana `reading` key, a Korean `hanja` key, or nothing). Parsed parts are `{part, reading, meaning}`; a Korean `hanja` lands in `reading`. Lookupper's Looktionary has such fields (its card table has Reading, Synonyms, Parts…), but its prompt runs on its server and is not in the exe; these prompts are our own. A saved card prompt without the new markers gets them once after `{{translationField}}` (`cardPromptVersion` 2). `{{formField}}` (after `{{componentsField}}`; added once to saved prompts, `cardPromptVersion` 3) gets the editable "Prompt da forma" (`ai.formPrompt`, a `form` list of the grammatical features of the word as written: person, gender, tense…) in every language, plus the "Prompt da transliteração" (`ai.transliterationPrompt`, a `transliteration` of the word as written) for scripts other than Latin (`TRANSLITERATED` in word-card.js; not zh/ja, which have the reading), as Lookupper's card shows "3rd Person Singular · Feminine · Past Tense · Verb" and "fa-bāḍat" by the IPA. While "Corrigir erros de OCR com IA" (`ai.cardOcrFix`, default on; off also hides the prompt card) is on, a card prompt that asks for the card's JSON (`takesCardNotes`: the card markers, or a `"headword"` key in a custom prompt; since 2026-10-27) and not for `"ocrFix"` itself ends with the editable "Prompt de erros do OCR" (`ai.ocrErrorsPrompt`; emptied, no note is sent, as with every prompt: see "Empty prompts"), a paragraph of its own (no marker, no variable, so it stays in the cached system message): the word and context come from OCR, so a word that is not real or does not fit is recovered from the context and described, with `"ocrFix": "<as given> → <described>"`, shown as an outlined "OCR: …" chip and kept in saved words. `{{ocrErrors}}` gets the script's typical misreadings (`OCR_ERRORS` in word-card.js: Arabic dropped letters and prefixes, CJK lookalike characters and wrong word cuts, Korean syllables, Cyrillic, Greek; else other-script or Latin rn/m and accents). It replaced the Arabic-only `ai.arabicOcrPrompt` of the same day, which is dropped from saved options. The context translator has its own switch and prompt in its tab (per-dictionary rule): `ai.contextOcrFix`/`ai.contextOcrPrompt` (`contextPrompt()` in word-card.js appends the note after the translation prompt; the popup uses it for the request and its cache key), default on, sharing `{{ocrErrors}}` (`ocrErrorsFor`, `ocrNote`), in the cached system message. The pictures have no OCR note: with "Usar a palavra corrigida pelo card" (`ai.imageUseCardWord`, default on) they search the word the card corrected (`imageWord` in images.js, from `ocrFix`), waiting for a card being made (`lookup.cardDone`); off, the OCR's word. The image request is keyed by the word searched (`imagePromptKey`). The pop-up shows the reading by the headword, then the transliteration (italic), IPA, the form chips before the part of speech, then "Sinônimos" and "Componentes"; saved cards and the Words tab keep them. A headword that starts with an RTL letter makes the title row and chips `dir="rtl"` (word at the right, as in Lookupper); each chip is bidi-isolated. Anki: `{ai-card}`/`{ai-card-plain}` carry them, with markers `{ai-reading}`, `{ai-transliteration}`, `{ai-form}`, `{ai-synonyms}`, `{ai-components}`, `{ai-components-plain}`; the form also joins `{tags}` and the AI glossary's tags; `{reading}` is the pinyin or kana when there is one, else the IPA.
- **Translations and the OCR note (2026-10-27):** no new key: the default "Prompt da tradução da palavra" (`WORD_TRANSLATION_PROMPT`) asks, in the one `translation` string, for the best translation of what the card describes, then, separated by commas, up to two other translations of exactly this meaning, only when there are some ("terminou, concluiu"); the pop-up, saved words, Anki and exports show that string as before. A `translationAlternatives` key was tried in de30300 and taken out at the user's request. The default card prompt's keys (headword, IPA, definition, translation, synonyms) describe what the card describes, the word or its longer unit; `form` and `transliteration` stay the word as written. The OCR note is conservative: only a clear misreading of characters gets `ocrFix`; rare words, names, slang, dialect, inflections and terms stay; a longer unit, a word cut elsewhere and a word's parts are not misreadings, and `{{ocrErrors}}` lists only misread characters (no word cuts or spaces for zh/ja/ko). Saved prompts still on an earlier default move to these (`LEGACY_CARD_PROMPT`, `LEGACY_WORD_TRANSLATION_PROMPT`, `SINGLE_WORD_TRANSLATION_PROMPT`, `LEGACY_OCR_ERRORS_PROMPT`); edited ones stay. Pictures: the unit found in the text (its headword), else the OCR fix, else the word as read.
- **Meaning in context first (2026-10-27, at the user's request):** the default card prompt starts with `CONTEXT_RULE` (word-card.js): the meaning in this context, not every dictionary sense; when the wording is anomalous (a mistranslation such as 사랑은 … 종류이다 for "love is kind") and the context clearly points to a different intended meaning, translation, definition and synonyms give that meaning, the definition says it is inferred and what the words literally mean, and headword, form and components stay those of what is written (headword 종류, the copula 이다); uncertain inferences are hedged; polysemy, figurative use, slang and dialect are not anomalies; a meaning mismatch is not an OCR error. `SYNONYMS_KEY` asks for synonyms or near-synonyms in the same language with the meaning the card gives (the intended one when inferred), not other senses of the headword (so 다정하다/상냥하다/친절하다 there, 유형/부류 for 여러 종류의 빵). Universal text with no example, in the cached system message (+~625 characters, ~140 tokens); the five expression examples are unchanged; test cases (hand-written replies, not model output) are in scripts/fixtures/contextual-meaning.json. `UNIT_CARD_PROMPT` and `HEADWORD_SYNONYMS_KEY` keep the earlier default for migration: a card prompt exactly on it (or on `LEGACY_CARD_PROMPT`) moves to `CARD_PROMPT`; an edited one keeps its words, an emptied one stays empty.
- **Headword display form (2026-10-27, at the user's request):** `headword` is the canonical dictionary form (the default asks for it "spelled as dictionaries of the language spell it, with the letters and marks of that spelling and no added stress or length marks", so Greek tonos, Portuguese/Czech/Turkish/Romanian letters and Arabic marks stay, and nothing is added); the optional `displayHeadword` is the learner-facing form. `{{displayField}}` (right after the headword in `CARD_PROMPT`) gets `headwordDisplayInstruction(ocrLanguage)`: Russian, Ukrainian and Bulgarian, the headword with an acute U+0301 on its own stressed vowel (one per word, the lemma's stress, not the surface's: дома́ → до́м; none on ё in Russian; "" when unsure); Latin, macrons on long vowels (length, not stress); every other OCR language nothing (Greek's lemma is already accented; Chinese/Japanese have `reading`; Czech/Slovak/Hungarian acutes are length; no Serbo-Croatian pitch accents, no Arabic vocalization, no Japanese pitch accent). `validDisplayHeadword(card, ocrLanguage)` accepts it only when, in NFD, it is the headword plus that language's mark on its vowels (`STRESS_VOWELS`: ъ is a vowel in Bulgarian only; ї takes it in Ukrainian), at most one acute per word; else '' and the headword is shown (so a half-streamed or wrong form never shows). `parseCard` NFC-normalizes `headword` and `displayHeadword` (ἀρχή keeps its breathing; decomposed and precomposed are one). Used only for display: the pop-up title, the saved card (`savedDisplayHeadword` re-checks against `dictionaryForm` and `language`, so an edit drops a stale one), the Palavras field "Forma exibida", the CSV's new last column "Forma exibida", Anki's `{ai-card}`/`{ai-card-plain}` and the new `{ai-display-headword}`; `{expression}`, lookups, audio, duplicates, images, cloze and selection keep the headword or the text. Only the previous default (`CONTEXT_CARD_PROMPT`) migrates; an edited prompt gets no marker (the user can add `{{displayField}}` or ask for `"displayHeadword"`). No Ancient Greek OCR option exists; the Unicode path is ready for one. Prompt growth: about 130 characters in every language, about 380 in Russian, Ukrainian and Bulgarian, in the cached prefix.
- **OCR surface first (2026-10-27, at the user's request):** `payload.word`, the word the OCR read, is the lexical target everywhere; lemmas are fallbacks. Dictionaries: `Pick::candidates` (words.rs `pick_analyzed`) and typed text (`manual_candidates`) start with the word as written, then the analyzer's dictionary forms, then the unspaced prefixes; `dict::lookup` takes, per dictionary, the first candidate it has, so its entry for 進めて wins over 進める when it has one. The lemmas also travel apart (`Pick::lemmas`, `LookupPayload.lemmas`, skipped when empty), which `cardHints` reads (older payloads: the candidates before the word). Word audio (`wordAudio` in audio.js, used by the pop-up's speaker, its buttons and menu, autoplay and `{audio}`, and by saved words' `{audio}` through `wordAudioFile` in `noteContextFromCard`): every source asked for the word on screen first, in the user's order, voices reading it; then, recordings only, the word lowercased by its locale (sentence-initial capitals, Turkish İ); then recordings of the AI headword and the first entry's headword, renamed "<source> · <form>" and `fallback: true`. `audioSearchTerm` is NFC and, only in ru/uk/bg, drops U+0301 (Шелестя́т → Шелестят); ё, й, ї, Bulgarian ѝ, Greek, Arabic, Latin-script marks and CJK stay. Display: the card's title is `validDisplaySurface(card, payload.word, lang) || payload.word` (the AI's optional `displaySurface`, the word as written with its stress marked in ru/uk/bg or macrons in Latin, checked letter for letter like `displayHeadword`); under it, when it is another word (`sameWord`), "Forma de dicionário: <displayHeadword || headword>". Saved cards the same (`savedDisplaySurface`), and the Palavras tab has "Palavra exibida" and "Forma de dicionário exibida"; the CSV ends with those two columns. Anki: `{expression}` stays the headword; new `{surface}` (the word read) and `{display-surface}`. {{displayField}} asks ru/uk/bg/la for both keys; the approved card prompt text is unchanged.
- **Analyzer provenance in the card hints (2026-10-27):** `Segment::name` (Rust) is "sudachi", "jieba", "kiwi", "mecab-ko-dic" (lindera, where Kiwi has no build) or "arabic-heuristic"; `Pick::analyzer` is it, or "generic" for words.rs's own rules, and `LookupPayload.analyzer` carries it (typed text: the analyzer only when it gave dictionary forms; not sent when empty). `cardHints` names the kind of evidence: Sudachi/Kiwi/mecab-ko-dic forms as "morphological lemma candidates (X)" of the written form, not its meaning nor an OCR fix; jieba as a segmentation guess at word boundaries, plus "CC-CEDICT has an entry for it" only when the lookup's `entries` hold an entry of a dictionary named CC-CEDICT matching the word as read (no entry: nothing said); the Arabic splitter's cut as heuristic only when it cut the word out of a run; "generic" only in unspaced scripts (the run from the pointer is a guess); in spaced scripts the spaces make the word and nothing is added. No confidence values. A payload without `analyzer` gets the forms as "the word analyzer's dictionary forms", as before.
- **Longer units in the AI card (prompt `ai.expressionsPrompt`, "Prompt das expressões"; emptied, the note is not sent. The "Reconhecer expressões" switch, `ai.cardExpressions`, was removed on 2026-10-27, see "Empty prompts"):** the word on screen is a starting point; when it belongs to a larger unit in its context ("Socrates" in "the Socrates Awards", "turned … off", 学 in 学习, an idiom), the card describes the unit. Same request, no second call.
  - `EXPRESSIONS_PROMPT` (word-card.js) follows a card prompt that asks for the card's JSON (`takesCardNotes`: `{{…Field}}` markers, or a `"headword"` key in a custom prompt) and not for `"selection"` itself, before the OCR note, as a fixed paragraph with exactly five examples (Socrates Awards, macht … aus, 学习, وبكتابهم kept whole, massa kept with its slang sense), so it stays in the cached system message. A saved card prompt is not rewritten; any other prompt goes as written, and the two switches say so in Dicionários (`cardNotesWarning`). More cases, negatives included, are test data only: `scripts/fixtures/semantic-selection.json` (never sent).
  - The reply's optional `"selection": {"parts": [pieces as written in the context], "type"}`, parsed by `parseSelection` (src/lib/ai/selection.js; "a ... b" in one piece is split). The AI never gives positions: `locateSelection(context, contextAt, word, selection)` finds the pieces as code point ranges. A piece must overlap the word at `contextAt` (or its only occurrence when `contextAt` is missing); the others are the nearest before and after it, at most 80 code points apart, with no sentence end between them; a piece may not cut a word of a spaced script (except at the word's own edges); spaces match runs of spaces; case is ignored. Not found, ambiguous, or just the word: null, and the word is marked as before.
  - `headword` is the unit's dictionary form ("turn off"); `payload.word` stays the word as read. The pop-up marks each range in Contexto only on the finished card (never while streaming). The card's `selection` is only the AI's proposal; `lookup.contextMarks` (set when the card is done) is what was found, and only it places anything: the Contexto marks, saved cards (`selection` kept as proposed, `contextMarks` as found, `contextAt` for the word; marks checked against `context` before use), the Anki cloze and the pictures. Headword and definition always show what the AI described, so they stay consistent with each other. Anki: `{expression}` is the headword; `clozeAt` (`clozeRange`: the unit when it is one piece, else the word at `contextAt`, in `context` code points) is moved into the sentence that holds it (`rangeWithin`), so a repeated word or unit clozes the one looked up; without it, the first match of `clozeWord` or the word, as before. The pictures, with "Usar a palavra corrigida pelo card", search the unit's headword only when it was found (after an OCR fix).
  - When the word is in its context more than once, `cardHints` quotes a piece of the context that holds the one on screen and is in it only once: "The word on screen is the '{{target}}' in '보호하고, 항상 인내'." (`locator` in selection.js, since 2026-10-27 at the user's request; it replaced "the second of the 2 times …"). Any match counts as a repeat, inside another word too, because the AI sees those: the OCR runs words together ("희망항상", "항상신"), and a whole-word count (`occurrence`, still in selection.js) then disagreed with what the AI counts. The piece first takes the rest of the word the match is in, then a word (a character in unspaced scripts) on each side at a time, up to 120 code points (else no note). The full context still goes in `Context:`. It is a `{{target}}` line, so it goes to the user message and changes the cache key only then.
- **Empty prompts (2026-10-27, at the user's request):** an empty prompt is the user's choice, never a request for the default. `promptText(value, fallback)` (word-card.js) is the one rule: a string is sent trimmed, so an emptied or spaces-only prompt is '' and its instructions are not sent; only a missing or non-string setting gets the default. `normalizeAiOptions` keeps an empty prompt as saved (only a missing or non-string one gets the default), so it survives saving and restarting; "Restaurar padrão" writes the default back. Every editable prompt follows it: `customPrompt`, `cardPrompt`, `contextPrompt`, `wordTranslationPrompt`, `readingPrompt`, `componentsPrompt`, `formPrompt`, `transliterationPrompt`, `ocrErrorsPrompt`, `expressionsPrompt`, `contextOcrPrompt`, `imageQuerySystemPrompt`, `imageQueryPrompt` (and the system prompts, which were already allowed empty). Supplementary prompts, emptied, drop only their key or note from the card (its marker becomes nothing, the JSON list stays well formed): translation, reading, components, form, transliteration, expressions, the card's and the translator's OCR notes; a switch and its prompt must both allow it (`cardComponents`, `cardOcrFix`, `contextOcrFix`, `showWordTranslation`). A custom card prompt that asks for a key itself keeps it: the generated keys only fill the markers. Main prompts, emptied, send nothing: the card (`cardPrompt` gives ''), Explicar and the context translator show "O prompt … está vazio" in their section (`emptyPromptHint` in the popup) and make no request; an emptied image query user prompt asks the AI nothing and searches the word; an emptied image system prompt sends the query with no system prompt. The request key is the prompt as sent, so emptying or restoring a prompt never reuses an earlier answer. Migration of the removed switch: `cardExpressions: false` empties `expressionsPrompt`; a prompt of the user's own (not the default) is kept in `expressionsPromptBackup`, never sent, and Dicionários shows "Recuperar" to put it back; the key is then dropped.
- **AI providers per dictionary:** each AI dictionary in the Dicionários tab has its own provider block, and a change there affects only that dictionary. The block holds the provider, its accounts (key, model, thinking, routing, extra JSON), temperature, streaming and "Cancelar pedidos pendentes" (`PROVIDER_FIELDS`), plus a system prompt for the card and the translator. "IA — palavra no contexto" keeps its block at the top of `ai`, as in the fork. The context translator and "Imagens" keep theirs in `ai.sectionProviders['ai-context' | 'ai-images']`. `normalizeAiOptions` fills a missing block with a copy of the word card's, so older settings keep working with the same key. Requests use `aiOptionsFor(ai, id)`: the shared prompts plus that dictionary's block. The popup's `optionsOf(kind)` maps card/explain → ai-word, context → ai-context and images → ai-images. Cancelling follows each dictionary's own switch (`keyKinds`, `keepRunning`). Each dictionary also has its own automatic switch: `autoGenerateOnLookup` (card), `autoExplain`, `autoTranslateContext` (which starts from `autoGenerateOnLookup` for older settings) and `autoShowImages`. Settings files strip and restore `apiKey` at any depth, including in `sectionProviders`.
- **Prompt layout for the providers' caches (`_splitPrompts` in ai-provider.js, every provider):** DeepSeek, OpenAI, Gemini and OpenRouter reuse a request's prefix, so what every lookup shares goes first. A line holding `{{target}}` or `{{sentence}}` moves to the end of the user message, the lines with the sentence before those with only the word (several words of one paragraph share it). All other lines, the system prompt's then the prompt's, make the system message. A line in both is sent once. A prompt without either variable is sent as written. The default explanation and context prompts keep each variable on its own line; saved old defaults are migrated (`LEGACY_EXPLAIN_PROMPT`, `LEGACY_CONTEXT_PROMPT`). Through OpenRouter, `anthropic/` and `google/` models get `cache_control` on the system message. `_logCacheUsage` logs the cached prompt tokens a reply reports.
- **AI cache:** same semantics as the fork. It has a 60 s TTL, joins in-flight requests and never caches partial or failed answers. `cancelPendingExcept` drops requests the pop-up no longer shows.
